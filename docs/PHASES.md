# Light Winter Technologies Implementation Phases

## Release 1 - Core Production Non-Fiscal

1. Product foundation and design system.
2. Shared business domain model.
3. Authentication, roles, and security.
4. Device identity, activation, and enrollment.
5. Strict random Python token licensing.
6. Anti-date-cheat license enforcement.
7. POS sales engine.
8. Full/partial void and full/partial return.
9. Inventory core.
10. Receipts and backup basics.
11. Sync basics.

## Release 2 - Serious Inventory and Multi-Branch

Advanced stock movement, purchasing, transfers, counts, supplier tools, dashboards, and stronger sync health.

## Release 3 - iOS and Windows Parity

Same activation, licensing, anti-date-cheat, receipt, reporting, sync, and owner workflows across Apple and Windows devices.

## Release 4 - Fiscal Readiness

Tax groups, fiscal readiness checklist, fiscal queue, open day, close day, fiscal diagnostics, and the API documentation gate.

## Release 5 - Commercial Domination Layer

Promotions, loyalty, BI/reporting, import tools, enterprise branch control, and premium polish.

## Locked Fiscal Gate

When fiscal readiness is reached, the app must clearly show:

`Fiscal Integration Stage Reached - Upload Fiscal API Documentation / Credentials to Continue.`

Fiscal build work must not guess provider credentials, endpoints, certificate rules, or final receipt signature rules. Those are supplied from the correct fiscal authority/provider documentation.
